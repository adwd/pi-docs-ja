# tmux で Pi を実行する

Pi は tmux 内で動作しますが、tmux では `Shift+Enter`、`Ctrl+Enter`、および通常の `Enter` が同じキーとして報告されることがあります。Pi がこれらを区別できるように、拡張キーを有効にします。

## tmux のバージョンを確認する

```bash
tmux -V
```

tmux 3.5 以降では、以下の推奨 CSI-u 設定を使用します。tmux 3.2～3.4 では、旧バージョン向けの設定を使用します。

## tmux 3.5 以降で拡張キーを有効にする

`~/.tmux.conf` に次の行を追加します。

```tmux
set -g extended-keys on
set -g extended-keys-format csi-u
```

ターミナルが Kitty キーボードプロトコルを直接提供しない場合、Pi は拡張キーの報告を要求します。CSI-u は、修飾キーを tmux 経由で転送するための最も信頼性の高い形式です。

## tmux を再起動する

この設定は tmux サーバーに適用されます。確実に有効にするには、tmux セッションを終了して新しいサーバーを起動します。

コマンドラインからサーバーを停止する場合は、先に作業内容を保存してください。このコマンドは、そのサーバーが管理するすべてのセッションを終了します。

```bash
tmux kill-server
tmux
```

## 修飾キーを確認する

新しい tmux セッション内で Pi を起動し、次の点を確認します。

1. `Shift+Enter` を押すと、エディターに改行が挿入されます。
2. `Enter` を押すと、プロンプトが送信されます。
3. macOS および Linux では、`Alt+Enter` を押すとフォローアップがキューに追加されます。Windows および WSL では、デフォルトで `Ctrl+Q` を使用します。

これらのキーが依然として通常の `Enter` と同じように動作する場合は、tmux の外部にあるターミナルが修飾キーを報告できることを確認してください。[ターミナルを設定する](terminal-setup.md)を参照してください。

## tmux 3.2～3.4 を使用する

これらのバージョンは拡張キーをサポートしていますが、`extended-keys-format csi-u` はサポートしていません。次の設定のみを追加します。

```tmux
set -g extended-keys on
```

Pi は、これらのバージョンで使用される xterm の `modifyOtherKeys` 形式をサポートしています。tmux を再起動し、確認手順を繰り返します。

それより古いバージョンでは、修飾された Enter ショートカットに依存せず、tmux をアップグレードするか、tmux の外部で Pi を使用してください。
