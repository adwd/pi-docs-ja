# セッションとコンテキスト

Pi は会話をセッションとして保存します。そのセッションのアクティブな分岐が、次のモデルリクエストに会話履歴を提供します。セッションコマンドを使用すると、作業の続行、別の分岐の探索、モデルに送信する履歴量の削減ができます。

## セッションを続行または切り替える

`--no-session` を指定して起動しない限り、Pi はセッションを自動的に保存します。

```bash
pi --continue
pi --resume
```

`--continue` は、現在の作業ディレクトリで直近のセッションを開きます。`--resume` はセッションピッカーを開きます。対話モードでは、`/resume` で同じピッカーを開き、`/new` で新しいセッションを開始します。

`/name` または `--name` を使用して、識別しやすいセッション名を割り当てます。`/session` を実行すると、現在のセッションファイル、ID、メッセージ数、トークン使用量、コストを確認できます。

セッションピッカーでは、セッションの検索、名前変更、削除ができます。また、パスの表示、並び順の変更、名前付きセッションのみに結果を絞り込むこともできます。ショートカットについては、[キーバインド](keybindings.md#sessions)を参照してください。

## 分岐方法を選択する

Pi はエントリをツリーとして保存するため、以前の時点に戻っても、離れた分岐は消去されません。

| 操作 | 結果 | 使用する場面 |
|---|---|---|
| `/tree` | 現在のセッションファイル内を移動します | 関連する代替案をまとめて保持する場合 |
| `/fork` | 以前のユーザーメッセージから新しいセッションを作成します | 代替案を別の作業として扱う場合 |
| `/clone` | アクティブな分岐を新しいセッションにコピーします | 現在の状態を別個にコピーする場合 |

`/tree` では、ユーザーメッセージを選択すると、そのテキストがエディターに戻されます。編集して送信すると、別の分岐が作成されます。アシスタントの応答やその他のエントリを選択すると、エディターが空の状態でそのエントリの後から続行します。

分岐から離れる際、Pi はその分岐を要約し、移動先の分岐にその要約を添付できます。これにより、離れた経路のすべてのメッセージを含めずに、関連する作業を保持できます。

永続化されるツリーとエントリの種類については、[セッション形式](session-format.md)を参照してください。

## 会話コンテキストを管理する

モデルが受け取るのは、セッションファイル内のすべての分岐ではなく、アクティブな分岐です。Pi はその履歴を、システムプロンプト、検出されたコンテキストファイル、利用可能なツール、読み込まれたスキルの説明と組み合わせます。[Pi の仕組み](how-pi-works.md#context)では、これらの入力がどのように構成されるかを説明しています。

フッターには、現在のコンテキスト使用量が表示されます。アクティブなコンテキストがモデルの上限に近づくと、通常、Pi は古い履歴を自動的に圧縮します。圧縮では要約が追加され、直近のメッセージは保持されます。元のセッションエントリは削除されません。

手動で圧縮するには、`/compact` を実行します。要約で特定のトピックや決定を保持する必要がある場合は、指示を追加できます。自動圧縮と保持する履歴は、[設定](settings.md#compaction)で構成します。

プロバイダーが利用できない場合や要約リクエストを受け付けられない場合、圧縮が失敗することがあります。プロバイダーの問題を解決してから、`/compact` を再度実行してください。自動圧縮を無効にしても、手動コマンドは無効になりません。

しきい値、保持される境界、分岐の要約の動作、拡張機能のフックについては、[圧縮リファレンス](compaction.md)を参照してください。

## セッションストレージを管理する

デフォルトでは、Pi はセッションを作業ディレクトリごとにグループ化して `~/.pi/agent/sessions/` に保存します。別の保存先を選択するには、`--session-dir`、`PI_CODING_AGENT_SESSION_DIR`、または `sessionDir` 設定を使用します。CLI オプションの優先順位が最も高くなります。

一時的な実行には `--no-session` を使用します。一時セッションは、Pi の終了後に再開できません。

セッションのパスまたは ID がすでに分かっている場合は、`--session` を使用します。対話モードの開始前に既存のセッションから新しいセッションを作成するには、`--fork` を使用します。

## セッションをエクスポートまたは共有する

現在のセッションを HTML または JSONL として書き出すには、`/export` を使用します。アップロードしてビューアーリンクを取得するには、`/share` を使用します。Radius 認証が構成されている場合、Pi は Radius アーティファクトを使用します。それ以外の場合は、非公開の GitHub gist を使用します。

エクスポートまたは共有したセッションは、事前に確認してください。プロンプト、モデルの応答、ツールの引数、コマンド出力、ファイルの内容、拡張機能のメッセージが含まれる場合があります。

## バグを報告する

`/bug [description]` を実行すると、Pi の開発者向けの非公開レポートを作成できます。セッションのトランスクリプトを含めるか、省略するか、現在のモデルに問題の要約を依頼できます。トランスクリプトや生成された要約には機密性の高い会話データが含まれる場合があるため、確認してください。

レポートには、認証情報の値を除いた環境とプロバイダーの構成、および記録されたエラー診断情報が含まれます。`radius.pi.dev` を通じてアップロードするか、同じレポートを zip としてエクスポートして、自分で確認および共有できます。アップロードにログインは不要です。Radius 認証を使用すると、レポートがアカウントに関連付けられるため、開発者がフォローアップできます。アップロードに失敗した場合、Pi は zip のエクスポートを提案します。
